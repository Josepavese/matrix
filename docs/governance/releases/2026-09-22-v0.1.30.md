This release ships ACP elicitation end to end and the quality controls that
verify it. Elicitation is the first capability in Matrix that turns an agent's
question into a human answer, so the surface is deliberately narrow: a flat form
schema, primitive or enum fields, and http/https URL mode only. The answer path
is the same SSOT validator for the HTTP surface and the Telegram frontend, so a
crafted callback cannot carry more weight than a schema-valid answer.

The adversarial pass that preceded the release fixed 34 defects, five of them
found by fuzzing after the suite was already green. Every fix was verified by
removing it and confirming the test fails.

### Refactors required by the governance gate

The gate failed on the first run and the failure was legitimate: the new
surfaces had outgrown the file, function and package budgets, and seven branch
complexity warnings appeared. Files were split rather than budgets raised
wherever the split improved cohesion:

- `providers/telegram/elicitation.go` (691 LOC) into `elicitation.go`,
  `elicitation_flow.go`, `elicitation_render.go`, `elicitation_values.go`
- `providers/telegram/bot.go` (415 LOC) into `bot.go`, `bot_update.go`,
  `bot_elicitation.go`
- `providers/agents/elicitation_handler.go` into `elicitation_handler.go` and
  `elicitation_projection.go`
- `logic/session/manager_cleanup.go` (339 LOC) into `manager_cleanup.go` and
  `manager_cleanup_guard.go`

Hot functions were decomposed: `wireToNeutralElicitation` (23 branch points)
into mode-specific projections and a per-field projector, `validateElicitationValue`
(19) per declared type, `Store.ClaimDue` (14) into a single-record claim plus a
pure eligibility predicate, `Store.AppendEvent` (12) into sequence resolution and
persistence, `applyCallbackLocked` (11) into an action dispatcher with confirm and
pick handlers, `renderElicitation` (11) into field and footer rendering,
`cleanupRunOwnedForkParentOwnerFromStandaloneChild` (11) into a refusal
predicate, and `acpConversationFactory.NewClient` (58 LOC) into client
construction, handshake and capability assembly.

Package budgets were raised explicitly and in one dated block, because package
size cannot be reduced by splitting files; the alternative was deleting shipped
functionality. The raises are recorded in `code-governance.toml` with the reason
and the statement that the new baseline is not permission for further growth.
Quality warnings went from seven to zero and were fixed, not budgeted away.

  `providers/telegram` and `pkg/zedacp` also raised.
- Mutation testing (aggressive mutant types): **2,042 mutants killed, zero
  survivors** across eleven Tier A packages (`session` 705, `agents` 542,
  `zedacp` 234, `runtrace` 178, `runapi` 154, `vaultsec` 99, `rundelivery` 62,
  `zedacpstdio` 38, `elicitation` 15, `middleware` 11, `runconfig` 4).
  Mutator coverage ranges from 62% (`zedacpstdio`) to 100% (`runconfig`).
- Fuzzing: 14 targets covering every decoder that consumes external bytes. The
  campaigns found five defects: an unnamed form property, URL mode accepting
  non-web schemes (`A://0`, `ftp://`, `smb://`), an unknown callback action
  falling through to option 0, a whitespace-only callback token, and a nil-logger
  panic in the inbound ACP decoder. Each has a deterministic regression test.
- Gate: `scripts/quality_gate.sh` ratchets per-package coverage floors, fuzz and
  mutation campaigns, static analysis and governance. `--light` exists for
  resource-constrained hosts.
