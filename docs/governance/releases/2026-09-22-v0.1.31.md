## What Changed

### Test policy

`code-governance.toml` now carries a `[test_policy]` section. Every package with
production code must carry `Test*`/`Fuzz*` functions (benchmarks and examples do
not count); packages above 80 production lines must assert at least one
rejection, failure or degraded path, matched against a name pattern held in the
config; test lines must reach 10% of production lines for packages big enough for
the ratio to mean something; packages that decode external bytes must carry a
fuzz target; packages that define a wire contract must carry an end-to-end test.

Packages that do not reach the absolute minimum sit on a recorded baseline. A
baseline is a floor: dropping below it fails, rising above it is reported so the
number gets recorded, and once the policy minimum is met the entry is reported
for deletion. New packages never get a baseline. Exemptions exist but carry an
ISO date and a reason and are printed in every report.

### Debt reduction

Ten baselines were closed with failure-path tests, not happy-path padding:
`sidecar`, `runtimebroker`, `readiness`, `setupstate`, `a2astate`,
`providerdiag`, `agentdiscovery`, `sessioncmd`, `oslog` and `runpayload`. The
remaining 13 keep a baseline: ten lack a behaviour test, and `bootstrap`,
`filesystem` and `agentprobe` carry only one test function each. The measurements moved:

- packages below the policy minimum: 23 → 13
- behaviour tests: 274 → 297
- test lines: 23,177 → 23,654 (ratio 0.66 → 0.68)
- test files: 120 → 130

### The defect the tests found

`runpayload.Input` accepted `{"other":"x"}` and decoded it to an empty turn, so a
misspelled request key produced a successful run with no output — the failure
mode that is hardest to notice. The decoder now distinguishes "text present but
empty", which is a legitimate empty turn, from "text absent", which is a
malformed request, and rejects the latter. The HTTP surface and its tests still
pass.
