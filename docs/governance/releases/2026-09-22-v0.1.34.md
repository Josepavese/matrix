## Defect Found By The Clean-OS Check

The published Linux amd64 artifact was extracted and run in a minimal
`debian:stable-slim` container with an empty `MATRIX_HOME`. On that fresh machine
`matrix readiness` exited 1 with a raw storage error instead of reporting the
`vault file is missing` blocker that the readiness evaluator already knows how to
produce, hiding the rest of the report exactly when an operator needs it. A vault
that cannot be inspected is now a blocker: the command exits 0 (or 2 with
`--strict`) and prints the structured report, with a warning on stderr naming the
inspection failure.

After the fix, in the same container: `matrix version` reports the expected
commit, `matrix doctor` exits 0, `matrix readiness` returns `status: not_ready`
with `blockers: ["vault file is missing"]`, and `matrix vault migrate` followed by
`matrix vault backup` produces a backup file.

The Nido VM tooling referenced by the runbook is not installed on this
workstation; Docker is, and a container is what was used. This exercises the
artifact and the first-run path, not a second operating system.

## GitHub Actions

- CI run URL: https://github.com/Josepavese/matrix/actions/runs/35708420584
- CI conclusion: **success** — governance, lint, test, windows-codex-policy,
  build, release-dry-run and secret-scan all green
- Earlier green run on the code commit: https://github.com/Josepavese/matrix/actions/runs/35707888357
- Release workflow: the first attempt failed in the `release-gate` job with
  "Tagged commit ... is not reachable from origin/main" because the gate fetched
  `origin/main` with `--depth=1` before asking whether the tagged commit was an
  ancestor of it. With a truncated history that question can only be answered yes
  when the tag is exactly the tip. `goreleaser` was skipped, so nothing was
  published. The fetch now keeps the history it needs, the tag was moved to the
  CI-green tip, and the gate passed on the second attempt.
- Ordering: the commits were pushed first and the tag was created only after CI
  was green, as the runbook requires. The tag was moved from the pre-fix commit
  to the CI-green one, and the artifacts were rebuilt from it.
- CI found a defect that local runs could not: the new bolt round-trip test
  inherited the operator's vault master key and failed on a clean runner. It now
  sets its own key. The whole suite was then re-run with `MATRIX_HOME` and `HOME`
  pointed at an empty directory and the key variables unset, which is the closest
  local equivalent of a fresh runner.
- The seven previous releases (v0.1.30 and earlier) were produced without CI.
