## What Was Consolidated

Driven by `issues/2026-09-22-artifact-digest-verification-consolidation.md`, a
handoff note left by an agent working in another repository on this workstation.
The note reported the real problem precisely: the feature was split between the
pushed `5db4892` and the unpushed `aaf61da`, so a reader of the remote could not
tell whether artifact verification existed, was partial, or was absent. The note
is closed in `issues/closed/` with the evidence below.

- **Consolidated, not reworked.** After `aaf61da` there is one implementation of
  each idea: `describeArtifactVerification` is gone from `cmd/matrix` (it lives on
  `agentcfg.ArtifactVerification.Describe`), `RegistryClient.PlatformKey` is the
  single platform mapping used by both distribution resolution and the recorded
  evidence, and `fetchVerifiedArchive` is the only download-verify-extract path.
  The two commits did not conflict; only the history was split.
- **Merged result verified**, not either commit alone: `GOPROXY=off go build ./...`
  succeeds, `GOPROXY=off go test ./... -count=1` passes with 75 packages ok and
  exit 0, `golangci-lint run ./...` reports 0 issues, `gofmt -l .` is clean.
- **Live check re-run** against the real registry:
  `MATRIX_REGISTRY_INTEGRITY_REAL=1 go test ./internal/logic/agentmgr -count=1`
  passed in 85s with `status=verified`, the published and downloaded digests both
  `3046e0404fdc60fb80307e7a47824ba07477364178a4d09baa8548496dd6d43b`.
- **Real install in a throwaway `MATRIX_HOME`**: `matrix install opencode` printed
  `Verified sha256 3046e040… of opencode against the registry index for
  linux-x86_64`, and `matrix agent info opencode --source=local` reports the
  verification, the artifact digest and the installed version.
- **One defect fixed** from the note's open decisions:
  `agentdiscovery.localProvider.Get` loaded the agent metadata and then dropped
  `meta.Version`, so `matrix agent info --source=local` printed a blank version
  while the catalogue reported the persisted one for the same agent. The two paths
  now agree; the regression test fails without the fix, and an agent with no
  recorded version still reports empty, because unknown and installed are not the
  same fact. On the operator's own home this now shows `opencode` at `1.4.6`,
  which was previously invisible.
- The note's other two open decisions stand as documented: the index publishes the
  archive digest rather than the executable digest (the gate runs before
  extraction, and a self-computed digest would read as a verification it is not),
  and `npx`/`uvx` distributions have no artifact to verify.

## Licence Restored In The Archives

`archives.files` in `.goreleaser.yml` **replaces** GoReleaser's default file list,
which already contained `LICENSE*`. The published v0.1.34 archives therefore
carried no licence text, which Apache-2.0 does not allow for a redistributed
binary. Verified before this release:

- all six archives built by the snapshot now contain `LICENSE`, byte-identical to
  the repository (`sha256 c520262f7926651e`);
- `governance/manifest.toml` requires `LICENSE` in the artifact set, so it cannot
  be dropped silently again;
- the **published** `matrix_0.1.35_linux_amd64.tar.gz` was downloaded and checked:
  the licence is present and its digest matches the repository.

## Windows Validation

The v0.1.35 Windows artifact was installed and exercised on the same Windows 11
IoT Enterprise LTSC guest used for v0.1.34, with
`tests/windows_release_validation.ps1 -Version v0.1.35`. All nine checks passed:

That run also found a defect in the validation script itself: the version
assertion was hard-coded to `0.1.34`, so the script pinned itself to the release it
was written for and failed on any other. It now derives the expected version from
`-Version`.

## Warnings And Exceptions

- Accepted warning: `gemini: executable not found in PATH` from `matrix
  readiness` on the operator's workstation; the blocker list is empty.
- Accepted behaviour, by design: a digest mismatch refuses the install and there is
  no bypass flag. An upstream index that publishes a stale digest becomes a
  blocked install rather than a silent one; the error names both digests.
- Shared checkout: another agent session works in this repository. One of this
  release's commits (`5db4892`) was pushed by this workstream while containing part
  of that session's work; the consolidation above is what makes the remote
  coherent again. Commits from this workstream now list their paths explicitly
  instead of using `git add -A`.
- Not re-measured: the Tier A mutation baseline. The consolidated change adds no
  production code path beyond one deleted field read, and the mutation campaign
  was measured at v0.1.34.
- Open: no human security review, and no clean-OS validation beyond the Debian
  container, the Windows guest and this workstation.
