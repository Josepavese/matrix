## What The Release Contains

- **ACP generation negotiation** (`81ac017`): the client asks for the highest
  version it supports, retries once at v1 when an agent refuses the newer number,
  and records what was agreed; `authenticate`/`logout` are used for v1 and
  `auth/login`/`auth/logout` for v2. `AuthMethod` resolves `id` and `methodId`
  through one accessor, so an agent speaking either generation is understood, and
  ACP v2's structured `auth_required` error data is recognised before the text
  heuristics, with a depth-bounded walk because that data comes from the agent
  process. Matrix still does not advertise `capabilities.auth.terminal`: it does not
  implement the relaunch flow, and advertising it would be a claim rather than a
  capability.
- **Late-delivery proof on every watcher exit path** (`df8490e`, closes
  `issues/closed/2026-09-23-runaction-late-proof-lost-on-cancellation.md`): the
  watcher recorded that a live-context delivery never returned before its run ended
  only on its ticker branch, so a cancellation observed before the next tick left
  the delivery with no proof and the failed attach recorded a cancellation instead.
  The evidence an operator reads was decided by a race; it now cannot be.
- **Automated host half of the Windows validation** (`ce7a99e`):
  `tests/windows_validation_host.sh` serves the validation script, collects the
  report and judges it, with `--self-test` driving the whole collector on a host
  with no Windows guest. CI runs that in the `windows-validation-host` job.

## Windows

Not re-run for this release. The guest's writable overlay was deleted earlier the
same day to reclaim 4.9 GB; the base image and blueprint were kept, and
`docs/governance/windows_validation_2026-09-22.md` records the two commands that
rebuild the guest plus the one-time setup and the traps that cost time. What is new
here is that the host half no longer needs a person: serving the script, collecting
the report and judging it is one command, self-tested in CI. The remaining manual
step is typing two commands into the guest console, which needs OpenSSH or the QEMU
guest agent in the guest — work to do when the guest is next rebuilt.
