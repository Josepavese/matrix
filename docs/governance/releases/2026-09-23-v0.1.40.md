The largest security release of this series: the ACP v2 migration is complete, two
threat-model findings are fixed, and the release pipeline now ships an SBOM per
archive with build provenance — verified end to end on this release.

## What The Release Contains

- **ACP v2 complete** (`58a302a`): terminal authentication methods behind an opt-in
  whose single predicate drives both the advertisement and the runnable surface
  (launch the configured program with the method's args and env, non-zero or
  signalled exit is a failure, `auth/login` is never sent, and the connection is
  rebuilt and reinitialized before the gated operation is retried); structured
  `auth_required` with exactly one login and one retry; terminal methods offered on
  v2 connections. Two pre-existing gaps had to be fixed for any of it to be
  reachable: `doCall` flattened RPC errors so the marker could never survive, and the
  adapter rejected every response whose raw `protocolVersion` was not 1. The
  initialize request now uses the parameter names of the generation it requests.
- **Telegram allow-list enforced** (`7e71bf3`): closed to the threat model's High
  finding; the admins list was parsed and documented but never read.
- **Config writes confined** (`2485004`): `Config_Set` no longer writes wherever an
  agent tool call points.
- **SBOM and provenance** (`ef865d0`): one SPDX document per archive, and a Sigstore
  attestation over `dist/checksums.txt`, both verified by the release script.
- **Reproducible toolchain and lint** and the **quality gate now runs in CI**, which
  is what surfaced that the coverage floors were calibrated on a different Go
  release than CI built with.

## What Was Not Done

- **The tool-call authorization finding is still open**: an agent-returned tool call
  is executed without checking that the turn advertised it. It is the remaining
  concrete bug from the threat model and is tracked in
  `issues/2026-09-23-security-findings-from-threat-model.md`.
- **Three findings are decisions rather than defects** and remain open as such: the
  local HTTP API, A2A ingress and vault RPC are unauthenticated when their keys are
  unset (the shipped default); an install proceeds without an integrity check when
  the registry publishes no digest; and the registry index supplies the command that
  is launched.
- **The Tier A mutation baseline was not re-measured.** The campaign is opt-in and
  slow, and this workstation was running four parallel workstreams; running it
  against a busy machine would have produced numbers about the machine.
- **No v2 ACP agent exists here**, so the terminal flow is verified against the
  specification and test doubles, not a real peer.
- Windows was not re-run: the guest overlay was deleted earlier to reclaim disk, and
  the rebuild path is documented.
- No human security review.
