The supply-chain and protocol-surface release: unverifiable installs are refused,
the registry can no longer choose what gets launched, and the A2A JSON-RPC binding
answers the methods its agent card advertises.

## What The Release Contains

- **Unverifiable installs are refused by default** (`019b8f6`): an artifact whose index
  entry publishes no sha256 was previously installed after merely recording that fact,
  and nothing below verifies it - Matrix downloads a binary artifact itself with a plain
  HTTP GET, while the package managers that do verify their own tarballs are the npx/uvx
  path where Matrix downloads nothing. The operator who knows what they are doing can
  proceed with `matrix install <agent> --allow-unverified`, surfaced as a warning naming
  the artifact, a structured log event, and a persisted override that keeps the artifact
  marked `digest_not_published` and `verified=false` in `agent doctor` and `agent info`.
  Measured against the live index, this refuses 47 of 100 binary platform entries across
  nine agents.
- **The launch command is confined** (`019b8f6`): it came from the registry index and was
  used verbatim unless it looked local - a check that defeated its own purpose, since
  `./../evil` passed it and escaped the agent directory while an absolute `/bin/sh` was
  accepted as given. A command must now be a local relative path with a constrained
  alphabet, resolve inside the agent directory before the download, and exist as a file
  after extraction; npx and uvx package identifiers are validated, and a leading dash is
  refused because `npx -y -c <command>` would have run an arbitrary shell command.
  Compatibility is pinned against all 50 distinct command values and all 22 npm plus 2 uv
  packages the live index carries.
- **The A2A JSON-RPC binding dispatches** (`ec451a8`): it answered `-32601` to every
  method because the SDK dispatches PascalCase identifiers while the specification's
  JSON-RPC binding uses slash-separated names. The names are translated on the way in.
- **The ingress says what it accepts** (`bad0dba`): the doctor and readiness report now
  name the loopback ingress that accepts unauthenticated requests when no API key is
  configured, which is the shipped default.
- **Two small defects found by running the product rather than the tests**: a fresh PAL
  home logged a channel failure on every start because the Telegram seed file was simply
  absent (`0d75e56`), and the first-run guide told every operator to POST to a fixed port
  even when the runtime was bound elsewhere (`83bdf4c`).

`a2aSafeMetadataValue in internal/providers/a2a/metadata.go has 19 branch points (budget
10)` - and that file is **not part of this release**: it is uncommitted work from a
concurrent workstream that the checker sees because it reads the working tree. The
committed tree at `019b8f6` carries no budget failure, and CI confirms it. The tag was
cut before that was established, which is the wrong order: the preflight exists to be
understood, not stepped over, and the next release should confirm the failure belongs to
someone else's working tree before tagging rather than after.

  from the SDK or a server timeout, and two attempted fixes were reverted because their
  tests did not discriminate.
- **The ACP v2 and A2A completeness workstreams had not reported** when this release was
  cut; their changes are uncommitted and will follow in the next release.

  that also publishes a digest still wins. Each is recorded rather than implied.
- No human security review; no third-party A2A or ACP peer exists on this workstation.
