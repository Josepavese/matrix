## What The Release Contains

- **A2A task failure, cause found and fixed** (`c3cfb4d`). The cause was none of the
  guesses the issue recorded. Matrix's A2A notifier put the agent's progress payload into
  a status message verbatim; that payload carries a protocol SDK type while A2A metadata
  is a JSON object, the SDK's task-store validator rejected it, the task was stored failed
  with no message, and the SDK's execution errgroup then canceled the context - which is
  what appeared as "ACP prompt failed: context canceled" and the client eviction. There
  was no Matrix `cancel()` in the path and the request context was never the source, which
  is why two earlier fixes were tried and reverted. Metadata is now projected per value
  through JSON; reverting the projection reproduces the live symptom exactly in three
  regression tests.
- **A2A surface audited and completed** (`c3cfb4d`): every operation is served and tested
  or refused with the code the specification requires, `streaming: true` is backed by a
  test of the event sequence, push notifications and the extended card answer -32003 and
  -32004 when unconfigured, and a dispatch table asserts that none of the twelve method
  names answers -32601. Two terminal-state error codes remain deviations and are recorded:
  they are decided inside the SDK before Matrix code runs.
- **ACP v2 client completed** (`60dd565`): session capabilities were read only in the v1
  spelling, so every baseline method was reported unsupported for a conforming v2 agent
  and list, resume, close, delete and fork were unreachable; `auth/logout` was gated on a
  v1 marker, so a v2 agent could never be logged out; Matrix advertised capabilities v2
  removed and an `auth.terminal` shape v1 does not define; and authentication-required was
  read only from a data marker while the specification documents the code -32000, so a
  spec-shaped peer got no retry. All four fixed, each proven by reverting it.
- **A correction to my own earlier work**: A2A 1.0 uses PascalCase JSON-RPC method names;
  the slash-separated names belong to the previous generation. The translation added in
  `ec451a8` is backward compatibility rather than what a 1.0 client sends. The comment,
  the issue and this record now say so; no behaviour changed.

## What Was Not Done

- **The ACP v2 prompt lifecycle is not implemented**, and this is the largest remaining
  gap in the "complete product" sense: `SessionUpdate` carries no state or stop reason, so
  a `state_update` is dropped and a turn returns when the prompt RPC answers after a short
  quiet wait. Against a spec-conforming v2 agent that acknowledges insertion and finishes
  through an idle state update, Matrix can return early with partial output. Whole-message
  upserts, tool-call content chunks, plan and terminal updates, v2 diff changes and the v2
  permission fields are likewise unhandled.
- **No daemon-level A2A run against a real agent** was performed after the fix. The live
  symptom is reproduced deterministically at the handler, executor and router layers with
  the production metadata type, and the code path is pinned by the SDK sources, but a live
  process would close the last gap.
- **No third-party ACP v2 or A2A peer** exists on this workstation; the real peer in the
  tests is the repository's own mock binary as a real stdio subprocess.
- **Windows was not re-run** for this release; the guest was removed to reclaim disk after
  the v0.1.41 validation and is regenerable from the base image with the SSH flow now
  documented.
- No human security review.
