The release that closes the protocol work: the ACP v2 prompt lifecycle is implemented,
the A2A surface answers the error codes the specification requires, and the end-to-end
proof that was missing now exists.

## What The Release Contains

- **ACP v2 prompt lifecycle** (`60fe814`). The specification is explicit and the code did
  the opposite: a prompt response acknowledges insertion and "is not an `idle` signal",
  while completion arrives as an idle `state_update` carrying the stop reason. Matrix
  returned on the acknowledgement after a 150 ms quiet wait, so against a conforming v2
  agent it could return partial output. A v2 turn now waits for the terminal state, with a
  bounded budget that is reported rather than silent (`acp_turn_completion`,
  `acp_stop_reason`, `acp_turn_budget_ms`, a warning on exhaustion); v1 keeps its quiet
  wait behind a gate that a test fails without. The streaming shapes that were dropped in
  silence are now projected: message upserts with the specification's patch semantics,
  tool-call content chunks, plan and terminal updates, diffs, and the v2 permission
  fields. Terminal output and reasoning never become answer text, deliberately.
- **A2A error codes corrected** (`a3cd8ee`). Two codes were recorded as deviations because
  the SDK decides them before Matrix code runs; the correction turned out to be the SDK's
  own call interceptor. A terminal task now answers operation-unsupported - `-32004` on
  JSON-RPC, failed precondition on REST, where a subscribe used to answer not-found.
  Unknown ids still read as not-found, and a test drives the raw SDK to pin the
  uncorrected behaviour so an upstream fix is noticed.
- **A second A2A defect found on the way**: a message to a task whose turn was still
  running answered with the SDK's internal "execution is already in progress", which is
  not an A2A error at all. It is now the same operation-unsupported answer.
- **The end-to-end proof**: a real server on a real listener routes through a real session
  manager and a real router to the repository's own mock agent over real stdio, asserting
  a completed task whose artifact carries the peer's answer. Reverting the metadata
  projection fails it with the original live symptom; removing the name translation fails
  the legacy-name case with the production error. It is not a `matrix run` daemon - the
  test builds its own store and transport - and the test says so rather than claiming more.
- **A test-harness race fixed**: abandoning a one-frame SSE stream raced the reader against
  the response close and stalled the next request on that connection for about ninety
  seconds. Streams are drained to EOF; the suite now runs in milliseconds.

## What Was Not Done

- **No third-party ACP v2 or A2A peer** exists on this workstation. Every real-stdio
  assertion uses the repository's own mock binary, which the same workstream extended; the
  specification is the only independent authority the work could be checked against.
- **No true `matrix run` daemon-level A2A run**: the end-to-end test replaces the CLI vault
  and configuration bootstrap with a test store. Everything from the wire request to the
  agent process is production code, but the daemon path itself is not exercised.
- **`ListTasks` with `includeArtifacts` remains an accepted difference**: the SDK's task
  type omits an empty artifact list at the wire level, so emitting an empty array would
  need a transport body rewrite or a fork of the type. The specification's sentence is a
  lowercase "should" whose "must" half - omit when false - Matrix already meets.
- **Windows was not re-run** for this release; the guest was removed to reclaim disk and is
  regenerable from the base image with the documented SSH flow.
- No human security review.
