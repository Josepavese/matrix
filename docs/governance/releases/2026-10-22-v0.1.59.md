# Matrix v0.1.59 — governed typed run input

Run input now preserves ordered text/image content through the existing neutral
router, session and protocol contracts. Strict JSON rejects unknown/noncanonical
fields, duplicates and extra documents, including custom nested unmarshalling.
PNG/JPEG validation bounds encoded/decoded bytes, aggregate size and dimensions.
Unsupported content never falls back to a successful text-only task.

The input owner defines limits and a canonical payload digest. Request
idempotency includes the complete typed payload and source metadata; replays
perform no capability probe or new dispatch. Live capability checks belong to
the executing run, before the prompt, with its deadline, terminal failure code
and cleanup. Trace manifests record only type/MIME/size/SHA, excluding bytes and
arbitrary metadata. Model confirmation remains distinct from visual proof.

## Qualification

- Public API documentation updated with the supported contract, limits, byte
  lifetime, source assertions and capability/model distinctions.
- Unit/HTTP/race regressions cover strict decoding, safe errors, image limits,
  text/image routing, idempotency and source identity, terminal refusal codes,
  replay without new probes and ephemeral cleanup.
- Native candidate Matrix→OpenCode 1.18.31→`deepseek/deepseek-flash` succeeded on
  two independent synthetic pictures: red square and blue circle. The answer
  was absent from the textual prompt; selected/effective model was provider
  confirmed without fallback, both runs completed with strong cleanup.
- Repeatable opt-in test: `TestSmokeRealRichRunVision`. Default CI skip is not
  real-agent qualification. PAL runs strict JSON, payload and run API contracts
  natively on Linux/macOS/Windows.
- The first isolated bootstrap refused setup before any prompt. Its failure
  and replay were retained; the provisioned run used a new explicit attempt.
- No Vault schema change, data migration, device access or external VPS work.
