# Matrix v0.1.60 — verified tools-free roles and honest permission denials

A role that must return JSON from typed data no longer depends on a prompt
instruction to avoid native tools: an agent endpoint can require an ACP session
mode, and Matrix applies and verifies it before the prompt. A denied tool
permission is now diagnosable from structured ACP fields and, when the provider
ends the turn without an answer, the run is a terminal failure instead of a
completed one. The release is also built with the current stable Go patch from a
single toolchain pin, so the published assets carry the compiler the tree is
qualified on.

Two externally reported issues are closed by this release, each with declared
limits rather than as an acceptance of everything they asked:
[the Go patch release request](../../../issues/closed/2026-10-23-external-matrix-release-go-patch.md)
and
[the VICKY planning turn interrupted by a permission denial](../../../issues/closed/2026-10-25-external-vicky-json-planning-tool-permission-denied.md).
Acceptance is a decision to investigate and qualify a report; it is not a
commitment to build every part of it, as
[issue governance](../issue_governance.md) now records.

## Required ACP session mode

- `MATRIX_ACP_SESSION_MODE` is a per-agent-endpoint contract: exactly one mode
  identifier, validated at launch, ACP-only, refused when duplicated or when it
  conflicts with the Codex launch-policy contract.
- Matrix applies it on every `session/new` and on every reattach
  (`session/resume`, `session/load`). It verifies the result from a provider
  statement — the config-option `currentValue` returned by
  `session/set_config_option`, or an observed `current_mode_update` after
  `session/set_mode` — and fails closed before the prompt when the mode is
  unavailable, unconfirmed, mismatched or rejected.
- Reapplying on resume is deliberate: OpenCode 1.18.31 was observed to reset the
  session mode to `build` on resume after a successful mode selection.
- The launch contract is recorded as pending until the provider confirms; the
  confirmed evidence (`configured_mode`, `effective_mode`, `config_id`,
  `evidence_source`, `verification`) travels with the session and the turn
  result. Matrix does not claim to inspect a model request: the absence of
  tool definitions is the provider's guarantee, qualified here through a
  provider-side agent whose tools are disabled. Documentation:
  [Required ACP session mode](../../matrix_agent_session_mode.md).

## Permission denial: diagnosis and terminal outcome

- `permission.requested` inputs now carry `operation` and `operation_state`
  (`known`/`unknown`, always present), `tool_call_id`, `session_id` and the
  options; `permission.resolved` outputs carry `decision`, `option_id`,
  `provider_response` (`selected`/`cancelled`) and `denial_reason`
  (`trust_mode_off`, `no_allow_option`). Operation identity is derived only from
  structured ACP fields — v2 command/tool-call subjects, v1 `rawInput` and tool
  kind — never from free text or from a title. An unknown action is reported as
  unknown, not as an empty field.
- Provider failure classification adds `provider_tool_permission_denied`
  (HTTP 502, `provider.runtime.failed`), with bounded, redacted diagnostics and
  an authentication veto so auth failures stay `provider_auth_mismatch`.
- A turn that ends after a denied permission with no delivered answer (no output
  and no `agent.message.*` event) is now a **failed** run with that failure
  code, a `run.failed` event carrying `failure_code`, and no `run.completed`.
  `explain` states the terminal cause in EN/IT, keeps `uncertain=false`, and
  never reports `prompt_receipt=confirmed_by_result` for such a turn, including
  records stored as completed before this rule.
- A denial remains a negative answer to the provider, not evidence that Matrix
  granted anything: the observed turn is preserved as a refusal.

## Toolchain and release integrity

- `go.mod`'s `toolchain` directive is the single source of the Go pin
  (`go1.27.3`). All nine CI/release `actions/setup-go` steps read it through
  `go-version-file`, so the compiler that publishes artifacts cannot drift from
  the one the tree is qualified on.
- golangci-lint moves to `v2.14.0`: the previous pin could not read the export
  data version emitted by `go1.27.3` and failed before analysing anything.
- Coverage floors are unchanged. Under `go1.27.3` two packages measured just
  below their floors because the instrumented block counts shifted with the new
  toolchain, not because contracts lost tests; real contract tests restored them
  (`elicitation` 100.0%, `rundelivery` 98.2%) instead of lowering the ratchet.
  The code-governance ledger records the feature growth; the hard file and
  branch budgets are met by splitting `acp_adapter.go` into
  `acp_session_mode.go` and `explainRun` into cohesive helpers.

## What was deliberately not built

The following parts of the two reports were answered with a limit or left out by
design; they are not pending work dressed as delivered:

- **No guarantee narrated on the provider request body.** Matrix verifies the
  session mode the provider exposes and confirms; it does not inspect the
  request payload and does not claim the model received no tool definitions.
- **No consumer-shaped surface.** No VICKY or Half Pocket name, code, alias or
  branch exists in the product: the session-mode contract, the permission
  events and the failure code are generic, and the consumer's own vocabulary
  (`tool_permission_denied`) stays in the consumer.
- **No blanket "denial is failure" rule.** Only the structured, observable
  condition (denied permission, no answer, no agent message) is terminal; a
  legitimate denial remains a negative answer to the provider.
- **No rewrite of history.** Records stored as completed before this rule are
  explained truthfully but not relabeled in storage.
- **No native runtime qualification claim for the released assets.** The six
  published platforms are cross-built and provenance-attested; the skipped
  native Windows validation jobs are not presented as evidence they ran.
- **No consumer deployment.** No VPS, Hub, package or configuration outside this
  repository was changed; exposing the turn's `run_id`/`remote_session_id` and
  adopting the role contract remain consumer work, including human review.

## Limits

- No structured ACP error code exists for a permission denial, so the provider
  failure classification still reads provider text, conservatively, with an
  authentication veto; an abort worded only "cancelled" is not classified.
- The terminal denial rule requires the structured `decision=denied`; it does
  not infer a denial from event text. Any `agent.message.*` event or non-empty
  output counts as delivered.
- Legacy records already stored as completed are explained with the correct
  code, cause and receipt, but their stored status is not rewritten.
- The synchronous HTTP failure body keeps its existing generic shape (HTTP 500,
  no `code` field); the stable code is on the `run.failed` event, the local
  notification and `explain`.
- Matrix verifies the mode the provider exposes, not the provider's own request
  body. A provider without a mode surface fails closed; it is not approximated.
- No external VPS, Hub or consumer change was performed; VICKY adoption remains
  a consumer step. Inputs were synthetic; no client data was used.
