# Matrix v0.1.63 — the tool identity decides the action, not the result body

A public documentation run produced a trace that said the opposite of what
happened. Four read-only tools — two public page reads and one proof lookup —
completed with `status=ok`, `network_policy=public`, `kind=page_read` and one
`proof_record`, and requested no filesystem mutation. The same events exposed
`tool_name=read_file` with `heuristic_fallback/low` but `tool_kind=delete`,
`tool_effect=write` and summary `Deleted /workspace`; the proof lookup came out
as `kind=edit`/`effect=write` with `Updated /workspace`. An external consumer
saw a read become a deletion, and had no way to tell the claim was a guess.

This release answers that report:

- [ACP trace: public read results classified as filesystem delete/write with
  affirmative summaries](https://github.com/Josepavese/matrix/issues/18) —
  accepted: the defect is in Matrix's normalization, a fix is built here, and the
  consumer's decision to keep the upstream limitation recorded until this release
  is honoured by releasing it.

## Diagnosis

ACP `tool_call_update` is a patch: a field that did not change may be omitted
entirely, and `kind` is one of those optional fields. Matrix normalized every
update independently, so the identity already stated by the tool call was not
carried into its own result. With no kind in the patch, the fallback scanned
`name + content` for action words in rule order; a result body that quoted
"delete", "remove", "write" or "edit" therefore selected the action, and
`tool_summary.go` rendered an affirmative past-tense summary from whatever
absolute path the text happened to contain. The ACP metadata was not lost in
normalization — it was simply not in the patch, and nothing correlated the
result back to its call.

## The contract

- **Evidence is ordered and labelled.** A protocol `tool_kind` still wins. When
  the provider omits it, a declared tool identity from the canonical vocabulary
  (`read_file`, `list_files`, `search`, `write_file`, `edit_file`, `shell`)
  decides the kind as a low-confidence fallback. Free-form words are only used
  for a call, where the text describes what will be attempted.
- **A result body never selects the action.** Without a protocol kind or a
  declared identity, a tool result stays `other` with
  `tool_classification_source=unknown`, `tool_effect=unknown` and
  `tool_subject_kind=unknown`. It inherits the identity of the correlated call
  when the same `tool_call_id` window still has one: correlation is protocol
  evidence, not text inference.
- **Past-tense write summaries need a verified kind.** `Created`, `Updated` and
  `Deleted` are rendered only for a protocol kind or a declared identity. An
  unverified or unknown action keeps the neutral `Completed <tool>` form, so
  quoted public content can no longer become a filesystem write claim. A genuine
  write — protocol metadata or a declared write identity — keeps its summary,
  even when the result body happens to contain delete or remove words.
- **Heuristic evidence stays visibly heuristic.** A declared identity is not
  protocol metadata: the event keeps `heuristic_fallback`/`low`, and the trace
  contract documents that an unknown result is `unknown` rather than `other`
  with an effect invented from the body.

## Evidence

- Regression tests at both layers: the projection test covers page-read and
  proof-lookup results containing mutation words (including the request variant),
  the unidentified-result case, and the verified-write case; the notifier test
  runs the reported flow end to end — call declares `read_file`, the patch omits
  the unchanged kind and carries page text with delete/update words — and asserts
  `read`/`read_only`, the inherited low-confidence identity, the neutral
  `Completed read_file` summary, and the `tool_call_id` correlation.
- Before the fix, the same payloads projected as `kind=edit`, `effect=write`,
  `summary="Updated /workspace/docs"` (and `Deleted` when the quoted text only
  contained delete/remove words). After the fix the identical payloads project
  as `read`/`read_only`/`Completed read_file`, and a result without identity
  projects as `other`/`unknown`/`Completed tool`.
- Both governance gates pass. The `frontendevents` package ceiling is raised to
  its measured 880 LOC with a dated justification; no file, function, parameter
  or branch budget is relaxed, and the classification logic lives in
  `tool_classification.go` instead of growing `tool.go`.

## What was answered with a limit, not with code

- **A provider that sends only a result patch, with no kind, identity or prior
  call in the window, stays unknown.** Matrix reports that honestly as
  `other`/`unknown` with a neutral summary instead of guessing from the body.
  Recovering the identity requires an earlier call or protocol metadata; the
  trace cannot manufacture what the provider never stated.
- **A path quoted by result text is still listed as extracted evidence** in
  `inputs`/`outputs`, but it no longer selects the action, the subject or the
  summary. Rejecting text extraction outright would also drop the paths Matrix
  legitimately recovers for agents that narrate their calls.
- **No provider-specific mapping.** The identity vocabulary is the neutral one
  Matrix already documents; no agent name, framework alias or wire-format special
  case was added.
- **The consumer's retained private trace is not re-labelled here.** The reported
  trace is the consumer's evidence; this release changes what Matrix produces
  from now on, and the correction is published as a new immutable version rather
  than rewriting past bytes.
