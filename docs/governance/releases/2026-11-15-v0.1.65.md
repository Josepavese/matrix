# Matrix v0.1.65 — protocol freshness, and one stable ACP capability that was missing

A freshness pass over the two agent protocols Matrix speaks found the stable ACP
contract had gained exactly one client feature since the last pin, while the A2A
specification was unchanged and its Go SDK had moved one minor version. Matrix
now delivers the stable ACP client system prompt end to end and uses the current
A2A SDK; draft and release-candidate protocol surfaces are recorded as tracked,
not adopted.

## The contract

- **A client-owned system prompt is now a configured agent property.** The
  operator writes the instruction body to the agent configuration with
  `matrix agent system-prompt <agent-id> [--mode append|override]` (stdin for the
  body, `--show`, `--clear`). The neutral runtime carries a protocol-neutral
  `middleware.SystemPrompt{Mode, Text}`; no provider name or alias is introduced,
  and the body is stored as operator data, not derived from a provider.
- **Delivery is capability-gated before the session request.** The ACP adapter
  sends `systemPrompt` on session creation and restoration only when the agent
  advertises `sessionCapabilities.systemPrompt` (v1) or
  `capabilities.session.systemPrompt` (v2). Append is the default mode; `override`
  is sent only when the agent advertises the separately nested
  `mode.override` capability.
- **A configured prompt Matrix cannot deliver fails closed.** If the agent does
  not advertise the capability, or the operator asked for an unadvertised
  override mode, the run stops before creating or restoring the session with an
  explicit error. Matrix never silently falls back to the agent's own
  instructions while reporting the session as configured. No configured prompt
  means no `systemPrompt` field on the wire, not `null` and not an empty object.
- **The capability report names the surface.** `system_prompt` is a stable
  capability detail derived from the provider's own advertisement. The agent
  report adds `system_prompt_mode` and `system_prompt_bytes`; the instruction body
  stays hidden unless the report is explicitly asked to reveal values, following
  the existing env/header redaction rule.
- **A2A alignment is dependency-only.** `a2a-go/v2 v2.8.0` brings bug fixes for
  API-key placement, HTTP auth schemes, JSON-RPC errors from non-200 responses,
  malformed Unicode before signing, input-required history order, artifact
  recovery, null data/raw parts, `ServiceParams.With`, escaped tenant paths and
  cancellation of input-required tasks. Matrix's served and client A2A surface is
  unchanged; the SDK's new ACP executor, gRPC connection pool, structured-input
  extension, error sanitizer and agent-card caching are available upstream but are
  not adopted without a product requirement.

## Evidence

- New wire tests pin the stable `systemPrompt` shape on all three lifecycle
  requests, absence when unset, and the v1/v2 append/override capability read,
  including malformed markers staying unsupported.
- New adapter tests pin fail-closed behavior before a session exists, delivery on
  `session/new`, `session/resume` and `session/load`, and the advertised override
  requirement.
- New neutral-contract tests pin mode validation and the empty-body rule; new
  config-report tests pin prompt redaction and byte/mode reporting.
- A2A build and both A2A provider test packages pass on SDK 2.8.0. The full suite
  is green, the static quality gate passes with pinned golangci-lint v2.14.0 and
  govulncheck v1.6.0, and governance passes with measured package ceilings for the
  added capability. No file, function, parameter or branch budget was relaxed.

## What was tracked, not adopted

- **ACP v2 draft-only additions** after alpha.9 — session archive/unarchive,
  session status, title setting, proxy initialize/successor, auth status, speed
  category, plan path, prompt suggestions, tool-call/terminal cancellation,
  background work and the v2 message/replay/subagent shapes — remain experimental.
  Matrix does not present them as stable coverage and does not add compatibility
  aliases for them.
- **A2A `v1.1.0-rc`** — streaming live messages, timeline entries, optimistic
  concurrency, artifact generations and the deprecations it introduces are a
  candidate, not a stable requirement. Adopting it now would make Matrix serve a
  contract the specification has not published.
- **New A2A SDK optional surfaces** — no Matrix consumer exists yet; adding them
  would be speculative surface rather than protocol alignment.
