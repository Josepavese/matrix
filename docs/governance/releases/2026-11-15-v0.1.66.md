# Matrix v0.1.66 — ACP v2 becomes a qualified preview, not an accidental default

Matrix already negotiated ACP version 2 at the wire level. This release makes
that support intentional, observable and reversible: it qualifies the live
session path against released agents, reports the generation the connection
actually negotiated, labels version 2 as the upstream draft it is, rejects a peer
that declares version 2 while sending the version 1 payload, and provides a
per-agent version 1 pin. Version 1 remains the stable served path.

The adoption question was not "does the adapter know the v2 method names". It
was "which real agents accept this contract, what exactly was exercised, and how
does an operator roll one back". The answers are now in the release evidence and
in the runtime report, instead of in a protocol-version constant.

## Live qualification, 2026-11-15

The opt-in test is `tests/integration/acp_v2_commercial_real_test.go`. It does
not run in the default suite; it launches the endpoints named by environment
variables and may need a logged-in account and model tokens.

- **Codex ACP 2.6.0 — end-to-end pass.** Initialize negotiated version 2,
  `session/new` created a resumable session, the prompt was acknowledged and the
  turn ended on the terminal `state_update`, `session/resume` accepted the exact
  remote id, and `session/close` succeeded. The advertised system-prompt append
  path was exercised on `session/new`; an opt-in live `session/cancel` ended the
  turn with `acp_stop_reason: cancelled`; an opt-in permission prompt produced
  its command artifact and an opt-in `session/delete` succeeded. Codex did not
  send `session/request_permission` in that run, so its callback remains
  mock-covered.
- **Claude Agent ACP 0.107.0 — full pass through the configured gateway.** Live
  initialize negotiated version 2, the capability report exposed the v2 surface
  as draft, `session/new` returned a resumable session, the prompt was
  acknowledged and ended on the terminal `state_update`, and `session/resume`
  plus `session/close` succeeded. The local OAuth session is expired, so the
  run supplied the operator's Anthropic-compatible gateway environment through
  `MATRIX_ACP_V2_ENV_FILE`; the direct OAuth path remains unqualified. An opt-in
  live `session/cancel` also ended the turn with `acp_stop_reason: cancelled`;
  an opt-in permission run sent `session/request_permission`, trust mode selected
  `allow-once`, and the command artifact was created; opt-in `session/delete`
  and the system-prompt append path also succeeded.
- **Kimi CLI 1.3 — explicit rejection, then a working v1 pin.** Kimi declares
  `protocolVersion: 2` but sends the version 1 `agentInfo`/`agentCapabilities`
  payload. The strict check rejects the handshake with
  `ACP peer declared protocol version 2 but sent a non-conforming payload`.
  Pinning the agent to version 1 makes the handshake pass; doctor reports
  `provider_protocol_version: 1`.

The prompt, resume, close, delete, cancellation and (for Claude) permission paths
were exercised against the real agents. Codex did not request permission in the
recorded run, including a probe that asked for `approval_policy: on-request` and
a writeable sandbox; its callback, and terminal authentication for both agents,
remain covered by the mock-peer and adapter tests.

## The contract

- **Negotiation is explicit and observable.** The capability report now carries
  `protocol_version`, the generation the live connection agreed to. The doctor
  handshake result carries `provider_protocol_version`. Neither is inferred from
  the configured endpoint.
- **Version 2 is reported as draft.** On a version 2 connection every operation
  and content descriptor is `stability: draft` and its source names the v2 draft,
  even when a method keeps the same name as in version 1. Version 1 stays
  `stability: stable`. A stable-looking card on a draft connection was the
  reporting bug this release removes.
- **Conformance fails closed.** A version 2 reply must carry the version 2
  `info` and `capabilities` objects. A peer that declares version 2 but sends
  the version 1 names is rejected during initialize, not silently decoded into
  an empty v2 surface.
- **Rollback is one governed setting.** `matrix agent protocol-version
  <agent-id> 1` pins the handshake to version 1; `--clear` returns to
  negotiation. The pin is sent as the initialize request, so a pinned agent is
  never offered version 2 in the first place. The value validates as 1 or 2 and
  fails closed otherwise.
- **No v2-only path and no compatibility shim.** The decoder can still inspect
  either payload, but the adapter contract requires the generation it negotiated.
  Version 1 remains the fallback and the default for every peer that does not
  conform or refuses the newer number.
- **The probe follows the same path as the runtime.** `matrix agent doctor` now
  negotiates the configured generation instead of hardcoding 1, accepts the
  negotiated 1..2 range and reports the result. It is therefore able to show the
  same Kimi rejection and the same v1-pin recovery an operator sees at runtime.

## Evidence

- New live qualification test, documented above and in
  `docs/protocol_coverage.md`; recorded results for Codex 2.6.0, Claude 0.107.0
  and Kimi 1.3.
- New unit tests pin the protocol pin parser (including invalid values), the
  strict v2 payload check, and the draft/stable capability labels.
- New doctor test pins the negotiated version in the handshake result.
- Existing mock-peer tests continue to cover the v2 turn lifecycle, terminal
  authentication, cancellation and the v1 path.
- The committed release tree passes the full race suite, the governance manifest
  and the code budget through `scripts/release_gate.sh`; this note is published
  with that release evidence. The optional static lint/vulnerability steps are
  environment tooling, not part of this release gate.

## Limits

- Upstream ACP v2 is still `schema-v2.0.0-alpha.16`. This release does not claim
  stable v2, does not drop v1, and does not adopt draft-only features added after
  alpha.9.
- Claude's direct OAuth prompt path still needs a valid local login. The current
  credential has no access or refresh token, `claude auth status` reports
  `loggedIn: false`, and a run without the gateway environment fails at
  `session/prompt` with `OAuth session expired and could not be refreshed`. Its
  initialize/session/prompt/permission lifecycle is qualified through the
  operator's Anthropic-compatible gateway environment; that is a real prompt path,
  but it is not evidence that the OAuth path works.
- Codex did not send a permission request during the live run, even when the
  launch policy requested `approval_policy: on-request` and a writeable sandbox;
  only Claude's `session/request_permission` path was observed.
- The Kimi 1.3 result is specific to that installed legacy release. The v1 pin is
  the documented recovery; current Kimi source still negotiates only version 1.
- The release note records what was observed. Synthetic peers and a successful
  handshake are not promoted to "commercial v2 support" without the live entry
  above.
